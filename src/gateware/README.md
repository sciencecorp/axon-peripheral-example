# gateware

User project generated by `axon-sdk new`. Drop your peripheral RTL in,
declare it in `peripheral.yaml`, and the SDK takes care of wiring, build,
simulation, and deploy.

## Layout

```
.
├── peripheral.yaml          # Source of truth — peripherals, IO, msg types, sources
├── conftest.py              # Exposes SDK_ASSET_ROOT to per-peripheral tests
├── src/
│   ├── via_top.sv           # AUTO-GENERATED top wrapper (checked in)
│   ├── scir_sdk.rdf         # AUTO-GENERATED Radiant project (checked in)
│   ├── user.pdc             # Per-peripheral @AUTO pin blocks + your board pins
│   ├── user.sdc             # Per-peripheral @AUTO timing blocks + your board timing
│   ├── chip_peripheral_peripheral.sv
│   └── ...                  # Your peripheral SystemVerilog
├── test/
│   ├── tb/                  # Per-peripheral testbenches + cocotb tests
│   └── ...
└── build/                   # Codegen + Radiant outputs (gitignored)
```

`via_top.sv` and `scir_sdk.rdf` are auto-generated **and** checked in so the
project state on disk is the same state the next `axon-sdk regenerate` will
re-emit. If you hand-edit them, regeneration will refuse to overwrite — see
the `--force` semantics below.

## Build

`axon-sdk build --pdc devkit` regenerates `src/via_top.sv` + `src/scir_sdk.rdf`
from `peripheral.yaml`, rewrites the `@AUTO` blocks in `src/user.pdc` /
`src/user.sdc`, then invokes Radiant to produce a bitstream under `build/`.

Other build-side commands:

- `axon-sdk regenerate` — re-emits `via_top.sv` + `scir_sdk.rdf` without
  invoking Radiant. Refuses to overwrite either file if its checksum
  doesn't match the last codegen run — pass `--force` to acknowledge a
  hand-edit will be discarded. **Note:** this only protects the
  codegen-owned files. Your peripheral SystemVerilog and the
  `# CUSTOMIZE:`-marked regions in test files are never overwritten.
- `axon-sdk add-peripheral <name>` — appends a new peripheral entry to
  `peripheral.yaml` with a fresh `dev_peripheral_id`, scaffolds
  `src/<name>_peripheral.sv`, `test/tb/<name>_tb.sv`,
  `test/tb/test_<name>.py`, and re-runs codegen so the new peripheral
  lands in `via_top.sv`.
- `axon-sdk validate` — validates `peripheral.yaml` against the Pydantic
  schema, checks that every `dev_peripheral_id` lies in the
  user-assignable window (`0xF001..0xFFFE`), and confirms `fpga.sources`
  paths exist on disk. Run this before opening a PR.
- `axon-sdk deploy` — packages `build/` outputs into a deployable bundle
  (Debian package or raw bitstream, depending on profile).

## Simulate

`axon-sdk sim` runs the cocotb suites listed in each peripheral's
`verification.cocotb_tests` against the per-peripheral testbench wrapper.
Equivalent to `pytest test/tb/test_<name>.py`.

**cocotbext.axi configuration note.** The per-peripheral testbench drives
`rx_axis` / `tx_axis` through `cocotbext.axi`. To match the SDK frame
format (32-bit `tdata`, synchronous **active-high** reset), the test
scaffold instantiates the AXI-Stream master/sink with:

```python
AxiStreamSource(bus, clk, rst, byte_size=32, reset_active_level=True)
AxiStreamSink  (bus, clk, rst, byte_size=32, reset_active_level=True)
```

`byte_size=32` configures one beat per 32-bit word (no byte-level
unpacking). `reset_active_level=True` matches the active-high `rst`
convention used by every peripheral in this template (NOT `rstn`).

## Peripheral contract

Every peripheral module must expose the following ports verbatim:

| Port | Direction | Width | Notes |
| --- | --- | --- | --- |
| `clk` | input | 1 | MainController `clkmc` (80 MHz on via-devkit) |
| `rst` | input | 1 | **Synchronous active-high** reset — NOT `rstn` |
| `periph_addr` | input | 32 | `central_address \| dev_peripheral_id` |
| `rx_axis` | `axi4_stream_interface.secondary` | — | Decap'd packets in |
| `tx_axis` | `axi4_stream_interface.main` | — | Encap-bound packets out |

Frame format on `rx_axis` / `tx_axis`:

- 32-bit `tdata`, 4-bit `tkeep`, 8-bit `tid`, 1-bit `tdest`, 1-bit `tuser`.
- **Beat 0** is the header word: `{msg_type[15:0], len[15:0]}` (high half =
  `msg_type`, low half = `len` in bytes).
- **Beats 1..N** are the payload, packed **little-endian** into 32-bit
  words (LSB-first within each word; first payload byte → bits[7:0] of
  beat 1).
- `tlast` is asserted on the final beat of the frame.

The codegen wraps each peripheral in a decap/encap pair; do NOT prepend the
Axon header inside your peripheral.

## `dev_peripheral_id` window

`peripheral.yaml` IDs must lie in `0xF001..0xFFFE`. Values outside this
window are reserved for built-in peripherals (`0x0000..0xF000`) or the
broadcast address (`0xFFFF`). `axon-sdk validate` enforces the window.

## Constraint tiers

The SDK splits constraints into two tiers:

- **`src/scir_sdk.pdc` / `src/scir_sdk.sdc`** — board-level constraints
  (clocks, board pins, top-level timing). User-owned, byte-identical
  copies of the profile seed at project-creation time. The codegen never
  touches these after `axon-sdk new`.
- **`src/user.pdc` / `src/user.sdc`** — per-peripheral constraints. The
  codegen rewrites the `@AUTO <name>` blocks in place from
  `peripheral.yaml` `fpga.io[]` and `fpga.constraints.{pdc,sdc}[]`; edits
  inside an `@AUTO` block are blown away on the next regen. **Free-form
  lines outside any `@AUTO` block are preserved verbatim** — that's where
  you put hand-authored helpers (LDC-set clocks, pin overrides, etc.).

## Modification check

Codegen-owned files (`src/via_top.sv`, `src/scir_sdk.rdf`) carry a
`// AUTO-GENERATED — checksum: <sha256>` header at the top of the file
(for `.rdf`, the same marker in an XML comment: `<!-- AUTO-GENERATED — checksum: ... -->`).
Before regenerating, the CLI re-hashes the file body on disk and refuses
to overwrite if the checksum doesn't match the last codegen run.

Pass `--force` to acknowledge that any local hand-edit will be discarded.
`--force` semantics:

- Re-emit the file from the manifest without checking the recorded
  checksum.
- Update the checksum header to match the freshly-emitted body so the
  next regen run starts from a clean slate.
- The `@AUTO` blocks in `.pdc`/`.sdc` files are rewritten in place
  regardless of `--force`; hand-edits inside an `@AUTO` block are always
  discarded.

## Migrating an older axon-sdk project

If you started with the pre-SDK 4-file template (`example_peripheral.sv`,
`tb.sv`, manual `top.sv`, hand-authored `.rdf`), there is **no automatic
upgrade path** — the CLI intentionally refuses to migrate legacy layouts
so that the regenerate semantics stay clean. The OQ-5 walkthrough is:

1. **Bootstrap a fresh SDK project** next to the legacy one with
   `axon-sdk new <new_dest> --target via-devkit --peripherals <name1>,<name2>,...`
   matching the legacy peripheral name set.
2. **Copy peripheral RTL across.** Move each legacy
   `<name>_peripheral.sv` (or whatever the legacy file is called) into
   `<new_dest>/src/`, replacing the loopback stub. Match the port list in
   the "Peripheral contract" section above (clk, rst active-high,
   periph_addr, rx_axis, tx_axis); rename ports if the legacy module used
   different identifiers.
3. **Lift constraint hand-edits.** Move free-form lines from the legacy
   `.pdc` / `.sdc` into `src/user.pdc` / `src/user.sdc` **outside** any
   `@AUTO` block (free-form sections are preserved across regen).
   Per-peripheral IO that was hand-written in the legacy `.pdc` should be
   declared in `peripheral.yaml` under `fpga.io[]` so the codegen emits
   it inside the matching `@AUTO <name>` block.
4. **Run `axon-sdk validate` then `axon-sdk build --pdc devkit`.** Fix
   any structural errors the validator surfaces (most often: missing
   `fpga.sources` entries, `dev_peripheral_id` outside `0xF001..0xFFFE`).
   Once the build is green, retire the legacy project directory.
